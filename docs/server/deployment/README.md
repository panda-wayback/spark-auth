# 部署运行

## 目标

本机一条命令、镜像只挂一个数据卷即可运行，便于作为其它项目的依赖部署多个实例。

## 需求

- 本机：`make run` 一条命令完成建虚拟环境、安装依赖、迁移数据库并启动；依赖未变化时不重复安装。
- 镜像：只需挂载数据卷即可运行，不必设置任何环境变量；启动时自动迁移数据库。
- 服务端密钥：设置了环境变量 `SPARK_AUTH_SECRET_KEY` 时使用它；未设置时使用数据库同目录下的 `secret_key` 文件，文件不存在则首次启动自动生成。数据卷即包含数据库与密钥，备份或迁移数据卷即可。
- 健康检查：`GET /healthz` 在数据库可访问时返回 200，否则返回 503；无需登录，系统未初始化时也可访问。镜像内置健康检查，依赖方可等待 spark-auth 健康后再启动。
- 仓库提供直接引用镜像的 compose 示例；本机开发与 Docker 共用 `server/` 数据库的方式保留为单独的开发 compose。
- 一个数据卷只对应一个运行实例；多个项目各自部署实例互不影响。
- 管理员仍在首次打开网页时创建（见[管理后台](../admin-console/README.md)）。
- 请求来源 IP：请求带 X-Forwarded-For 时取其最后一项（最近一层反向代理看到的客户端地址），否则取连接地址；用于激活与核销记录的 IP。nginx 需配置转发该头，caddy 默认已转发。

## 方案

- 修改：`server` 的配置读取服务端密钥（环境变量优先，否则数据库同目录 `secret_key` 文件，缺失时生成）；新增 `/healthz`。
- 修改：`server/console` 的未初始化跳转放行 `/healthz`。
- 修改：`server` 的配置统一按上述规则确定请求来源 IP，各 Module 直接读取标准的请求来源地址，不各自解析代理头。
- 取舍：不经反向代理直接对外时，X-Forwarded-For 可被客户端伪造；IP 只供查看、不参与判定，因此不做可信代理列表配置。
- 修改：根目录 `Makefile`、`Dockerfile`、compose 文件。
- 取舍：密钥默认与数据库放在同一数据卷，部署零配置、不会出现"库在密钥丢"；代价是数据卷整体泄露即可伪造卡密（见[卡密管理](../key-management/README.md)的取舍），要求更高时用环境变量单独提供密钥。
- 取舍：镜像暂不发布到公共仓库，使用方本地构建或推送到自己的私有仓库。

## 不做

- 发布到公共镜像仓库与自动构建流水线。
- 环境变量创建管理员。
- 多个实例共享同一数据库。

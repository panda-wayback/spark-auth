# 卡密管理

## 目标

按软件签发自包含卡密，并控制卡密何时可用、何时失效。

## 需求

- 管理员创建 product 时选择类型：设备激活或按次数（见[按次数核销](../count-redeem/README.md)）；类型创建后不可改。以下有效时长与换设备相关的需求只适用于设备激活 product。
- 管理员按软件创建 product（如 software-a），并配置换设备策略：是否允许换设备、每次换设备扣减多少剩余时长（可为 0）；修改策略对该 product 下所有卡密的后续换设备立即生效。
- 管理员可禁用 product，禁用后禁止新激活、已激活设备校验失败；可取消禁用。
- 管理员可删除不在使用中的 product（规则见[管理后台](../admin-console/README.md)），其卡密批次与全部使用记录一并删除、已签发卡密失效；删除后标识可重新使用。
- 管理员批量签发卡密：填数量与有效时长；卡密短到便于手输（约 28 个字符，分组显示），难以猜测、无法伪造。
- 卡密有效时长从首次激活开始计算；未激活的卡密不过期。
- 每次批量签发生成一个卡密批次；管理员可禁用批次，禁用后该批次卡密不能用于新激活，已激活设备不受影响。
- 管理员可按批次或全部导出已签发卡密为 CSV。
- 管理员可查看 product 列表，并按 product 查看卡密批次与已激活记录。
- 所有管理操作须登录[管理后台](../admin-console/README.md)。

## 方案

- 新增：Module `server/keys`，负责 product 与卡密批次的数据、卡密签发、验证与导出；接口见 [server/keys/interface.yaml](../../../server/keys/interface.yaml)。
- 取舍：卡密只携带批次标识、序号与 HMAC 校验码，product 与有效时长由批次记录给出；只有服务端验证卡密，不需要非对称签名，卡密因此大幅缩短。
- 取舍：校验码由服务端密钥（`SPARK_AUTH_SECRET_KEY`）与批次随机值（存于数据库）共同对批次标识与序号计算；只泄露数据库或只泄露服务端密钥都无法伪造卡密，两者同时泄露才可伪造。代价是更换服务端密钥后，未激活卡密与已签发 token 一起失效。未设置环境变量时密钥自动生成并与数据库存于同一目录（见[部署运行](../deployment/README.md)）；要保持"只泄露数据库无法伪造"，需用环境变量单独提供密钥。
- 取舍：激活时要求序号不超过批次数量，即使密钥泄露，伪造范围也限于各批次原有数量，禁用批次即可止损。
- 取舍：不保存未激活卡密；同批卡密可随时由批次记录重新生成，服务端只保存 product、卡密批次、已激活记录与换设备记录。
- 取舍：每次签发生成独立批次，以便按批次禁用而不影响其它批次。

## 不做

- 分级别套餐。

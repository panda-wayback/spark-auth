# key 管理

## 目标

按软件分类管理产品（product）与激活密钥（key），控制 key 何时可用、何时失效，以及每个产品下的换设备策略。

## 要实现的

- 管理员可创建 product，每个 product 对应一款软件（如 software-a、software-b）。
- product 配置换设备策略：是否允许换设备、换设备时扣减的剩余时长（如 1 小时、1 天；为 0 表示不扣除）。
- 管理员可修改 product 的换设备策略，修改后对该 product 下所有 key 的后续换设备立即生效。
- 管理员可在 product 下生成 key；key 按所属 product 的策略换设备。
- 每个 key 设置有效时长（如 30 天），从首次激活开始计算；到期时间 = 首次激活时间 + 有效时长。
- 管理员可在 product 下批量生成 key：指定数量与有效时长，一次返回本批全部 key。
- 管理员可向 product 导入外部 key：上传 CSV（每行一个 key），导入时统一指定有效时长。
- 管理员可按 product 导出 key 为 CSV：key、状态、有效时长、到期时间（未激活为空）、当前绑定设备、换设备次数。
- 管理员可随时禁用 key 或 product，禁用后禁止新激活；也可取消禁用。
- 服务端可查询 product 列表；可按 product 查询 key 列表，列表展示状态、有效时长、到期时间、当前绑定设备、换设备次数。

## 关键约束

- product 标识唯一，如 `software-a`、`software-b`。
- key 字符串必须唯一、随机、难以猜测。
- key 只属于一个 product；激活时客户端须带上 product 标识，与 key 所属 product 不一致则拒绝。
- 所有管理员操作须先登录[管理后台](../admin-console/README.md)。
- 未激活的 key 不会过期。
- key 到期、被禁用，或所属 product 被禁用后，禁止激活，已激活设备的 token 校验失败。
- 允许换设备时，新设备激活会扣减 key 的剩余时长（提前到期时间），扣减量由 product 配置决定。
- 不允许换设备时，只有首次激活的设备可用，其他设备拒绝。
- 批量生成单次数量上限 1000；本批 key 全部生成成功或全部不生成。
- 导入的 key 须非空且全局唯一；文件内重复或与已有 key 重复时，整批拒绝并列出重复项。
- 导入全部成功或全部不导入。
- 第一版不做分级别套餐。

## 失败场景

- 管理员未登录。
- product 不存在或已禁用。
- product 标识重复。
- key 不存在。
- key 与客户端带上的 product 不一致。
- key 已到期。
- key 被管理员禁用。
- 批量生成数量小于 1 或超过上限。
- 导入文件格式错误、含空 key，或含重复 key。

## 解决步骤

1. 设计 `Product` 数据模型：标识、名称、是否允许换设备、换设备扣减时长、禁用状态、创建时间。
2. 设计 `Key` 数据模型：字符串、所属 product、有效时长、到期时间（首次激活时写入）、禁用状态、创建时间。
3. 在管理后台提供：创建 / 修改 / 禁用 product，生成 / 批量生成 / 导入 / 导出 / 禁用 key，查询 product 与 key 列表。
4. 激活与校验接口优先检查 product 与 key 状态。

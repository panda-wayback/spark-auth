# 设备绑定

## 目标

一个卡密同一时刻只在一台设备上生效，换设备按 product 策略处理并留下记录。

## 需求

- 用户在接入方软件中输入卡密激活，当前设备成为绑定设备；首次激活开始计时，到期时间 = 首次激活时间 + 有效时长。
- 同一设备再次激活只刷新 token：不扣减、不重新计时、不算换设备。
- 新设备激活：product 不允许换设备则拒绝；允许则替换绑定设备并扣减剩余时长。扣减后剩余时长不足则拒绝，原设备保持绑定。
- 被替换的旧设备再校验即失败。
- 接入方软件可随时校验当前设备是否仍然有效。
- 每次换设备留下一条记录（旧设备、新设备、扣减时长、换设备前后到期时间、换设备时间），只追加不修改；管理员可在[管理后台](../admin-console/README.md)查看。

## 方案

- 新增：Module `server/activation`，负责激活记录与换设备记录的数据，提供激活、校验接口及后台所需的查询与禁用函数；接口见 [server/activation/interface.yaml](../../../server/activation/interface.yaml)。
- 复用：`server/keys` 的 product 查询与卡密验证函数；接口见 [server/keys/interface.yaml](../../../server/keys/interface.yaml)。
- 取舍：激活记录与换设备记录归 `server/activation` 所有，其它 Module 只能通过它的函数读取或禁用，"换设备记录只追加"等保证由该 Module 独自负责。
- 接入方按[激活接入规范](../../client/activation/README.md)与[设备指纹规范](../../client/fingerprint/README.md)调用。
- 取舍：只在首次激活时校验卡密批次与校验码，之后只依据激活记录判定，因此禁用卡密批次不影响已激活设备。
- 取舍：激活成功后签发服务端签名的 token，校验时比对 token 中的设备与当前绑定设备，换设备后旧设备的 token 自然失效。

## 不做

- 校验响应签名（服务端签名 + 客户端 nonce + 客户端内置公钥验签）：暂不做。当前校验响应未签名，客户端无法识别伪造的服务器（如改 hosts 指向本地假服务）；做的话需为各客户端语言提供验签 SDK，并长期保管签名私钥。

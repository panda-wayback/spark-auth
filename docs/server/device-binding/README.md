# 设备绑定

## 目标

让一个 key 同一时刻只能在一台设备上生效；按所属 product 的策略决定能否换设备及换设备代价，并完整记录每次换设备。

## 要实现的

- 一个 key 同一时间只绑定一台设备。
- 首次激活时开始计时：写入 key 的到期时间（首次激活时间 + 有效时长）。
- 若 product 允许换设备：新设备激活时替换旧设备，并按 product 配置扣减 key 剩余时长（扣减时长可为 0，即不扣除）。
- 若 product 不允许换设备：只有首次激活的设备可用，其他设备拒绝。
- 旧设备被替换后，其本地保存的 token 校验失败。
- 服务端保存当前激活记录：key、device_hash、device_info、激活时间。
- 每次换设备写入一条换设备记录：key、旧设备（device_hash、device_info）、新设备（device_hash、device_info）、扣减时长、换设备前到期时间、换设备后到期时间、换设备时间。
- 管理员可按 key 查询该 key 的全部换设备记录。

## 关键约束

- 同一 key 只有一条当前激活记录。
- 首次激活不算换设备，不扣减、不写换设备记录。
- 已绑定设备上再次激活视为刷新，直接返回新 token，不扣减、不重新计时、不写换设备记录。
- 新设备激活且 product 允许换设备时：替换激活记录、扣减剩余时长、写换设备记录，三者同时成功或同时失败。
- 扣减后剩余时长不足（新到期时间早于当前时间）时，拒绝换设备，原设备保持绑定、不扣减、不写记录。
- 换设备记录只追加，不修改、不删除。
- 校验时必须同时满足：product 与 key 有效、未到期、device_hash 匹配。

## 失败场景

- 同一 key 在另一台设备激活后，原设备校验失败。
- product 不允许换设备时，非首次设备尝试激活被拒绝。
- 扣减后剩余时长不足，换设备被拒绝。
- 校验时 device_hash 与激活记录不匹配。

## 解决步骤

1. 设计 `Activation` 数据模型：key、device_hash、device_info、激活时间。
2. 设计 `TransferLog` 数据模型：key、旧设备、新设备、扣减时长、换设备前后到期时间、换设备时间。
3. 激活接口：验证 product 与 key 状态 → 判断首次 / 同设备 / 新设备 → 首次激活写入到期时间；新设备按 product 策略拒绝或替换（扣减剩余时长 + 写换设备记录）。
4. 校验接口：解析 token，核对 key 与 device_hash。
5. 管理后台：在 key 详情页查看换设备记录。

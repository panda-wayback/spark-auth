# 按次数核销

## 目标

让网页类服务（如网盘代下载）用按次数的卡密为任务收费：网页后端每核销一次卡密即可执行一次任务，次数用完卡密作废。

## 需求

- 管理员创建 product 时选择类型：设备激活（现有方式）或按次数；类型创建后不可改。
- 按次数 product 签发卡密时填数量与可用次数（1 至 10000），不填有效时长；同一批次的卡密可用次数相同，不同批次可以不同。可用次数 1 即一次性卡密。
- 卡密在次数用完前不过期；签发后可用次数不可修改。
- 网页后端把用户输入的卡密提交给服务端核销：卡密有效、所属批次未禁用、product 未禁用且为按次数、还有剩余次数，则扣 1 次并返回剩余次数，否则返回明确的失败原因。
- 同一卡密并发核销时，成功次数不超过可用次数。
- 核销成功即视为已使用，任务失败不退回；需要补偿时由管理员另行签发卡密。
- 按次数 product 的卡密不能用于设备激活；设备激活 product 的卡密不能核销。
- 每次核销留下一条记录（卡密、第几次 / 可用次数、核销时间、核销 IP），只追加不修改，只随软件删除一并删除；管理员可在[管理后台](../admin-console/README.md)按卡密查看：列表每个卡密一行（状态、已用 / 可用、首次与最近核销时间），点卡密进详情页看它的全部使用明细。
- 导出 CSV 时包含每个卡密的可用次数。
- 已有的一次性 product 自动变为按次数 product，其已签发卡密的可用次数为 1。
- 网页后端按[核销接入规范](../../client/redeem/README.md)调用；网页本身不在本仓库实现。

## 方案

- 修改：`server/keys` 的 product 类型改为设备激活 / 按次数；按次数 product 的批次记录可用次数，签发时指定；导出 CSV 增加可用次数列。
- 修改：Module `server/redeem` 的核销按批次可用次数计数，返回剩余次数；核销记录改为每次使用一条。接口见 [server/redeem/interface.yaml](../../../server/redeem/interface.yaml)。
- 复用：`server/keys` 的卡密验证与 product 查询函数；接口见 [server/keys/interface.yaml](../../../server/keys/interface.yaml)。
- 修改：`server/activation` 激活时拒绝按次数 product 的卡密。
- 修改：`server/console` 按次数 product 签发时填可用次数，卡密页按卡密汇总展示核销记录（代替激活记录），另有卡密核销详情页。
- 修改：`server/redeem` 增加按卡密汇总的查询与单个卡密的明细查询；数据表与核销接口不变。
- 取舍：列表按卡密汇总而不是每次一行，可用 100 次的卡密只占一行；状态「使用中 / 已用完」与删除软件时的「使用中」同义。
- 取舍：类型挂在 product 上，一个 product 下只有一种卡密，后台页面与规则都不用按批次分情况。
- 取舍：可用次数挂在批次上（与设备激活卡密的有效时长一致），同一软件可以签发 1 次、10 次等不同规格的卡密。
- 取舍：核销接口与激活接口一样无需登录、只需卡密；知道卡密的人才能核销，误核销只影响卡密持有者本人。
- 取舍：不做预扣与退回，核销即扣；接入方应在核销成功后再执行任务。
- 取舍：核销 IP 为请求来源 IP，核销接口不变、接入方不另传；由网页后端核销时记到的是网页后端服务器的 IP（可区分是哪个后端在核销），不是终端用户 IP；不做 IP 归属地；改造前已有的记录 IP 为空。

## 不做

- 按时长不限次数的网页卡密。
- 签发后增减卡密次数。
- 任务失败自动退回。
- 核销时附带备注（如分享链接）。
- MCP 接入说明中加入核销规范。

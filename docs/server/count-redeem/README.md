# 按次数核销

## 目标

让接入方用按次数的卡密为任务收费（如网盘代下载）：按剩余次数核销，次数用完或超用后卡密作废；与设备激活卡密是两种并列的卡密，接入方按业务选用。

## 需求

- 管理员创建 product 时选择类型：设备激活（现有方式）或按次数；类型创建后不可改。
- 按次数 product 签发卡密时填数量与可用次数（1 至 10000），不填有效时长；同一批次的卡密可用次数相同，不同批次可以不同。可用次数 1 即一次性卡密。
- 卡密在次数用完前不过期；签发后可用次数不可修改。
- 接入方可查询一张按次数卡密的状态（是否可核销、已用 / 可用 / 剩余），只读、不扣次数；从未核销过的卡密剩余等于批次可用次数。
- 接入方核销时提交卡密与可选次数 `count`（省略或为 1 时与「每次扣 1 次」相同）；`count` 为正整数且不超过上限（1000），非法则请求无效。
- 剩余次数 ≥ `count`：扣 `count` 次，返回扣后剩余；核销成功即视为已使用，任务失败不退回；需要补偿时由管理员另行签发卡密。
- 剩余次数 < `count`（余额不足）：整笔按超用处理——内部记下超用，剩余视为 0 或负（对外均表示已废卡），卡密此后不可再核销；接口返回失败，接入方不得执行任务。已用完（剩余 ≤ 0）后再核销同样失败、不再改动。
- 同一卡密并发核销时，不得出现「剩余被重复卖出」；超额或用尽后卡密作废。
- 按次数 product 的卡密不能用于设备激活；设备激活 product 的卡密不能核销。
- 每次核销留下记录（卡密、第几次 / 可用次数、核销时间、核销 IP），只追加不修改，只随软件删除一并删除；`count` 为 N 且未超用时写 N 条；超用时内部记录须能看出已用超过可用。管理员可在[管理后台](../admin-console/README.md)按卡密查看：列表每个卡密一行（状态、已用 / 可用、首次与最近核销时间），点卡密进详情页看它的全部使用明细；剩余 ≤ 0（含超用）视为已用完。
- 导出 CSV 时包含每个卡密的可用次数。
- 已有的一次性 product 自动变为按次数 product，其已签发卡密的可用次数为 1。
- 接入方按[核销接入规范](../../client/redeem/README.md)调用；接入方本身不在本仓库实现。

## 方案

- 修改：Module `server/redeem` 新增只读查询接口（卡密状态：已用、可用、剩余等）；修改核销接口支持可选 `count`；余额不足时内部记超用并将卡作废，返回失败。接口见 [server/redeem/interface.yaml](../../../server/redeem/interface.yaml)。
- 修改：`docs/client/redeem` 与 MCP 接入说明同步查询与批量核销约定，见[核销接入规范](../../client/redeem/README.md)、[激活接入规范](../../client/activation/README.md)。
- 复用：`server/keys` 的卡密验证与 product 查询；后台汇总 / 明细仍用 `server/redeem` 现有查询能力，展示上剩余 ≤ 0 即为已用完。
- 取舍：超额不「失败且余额不动」，而「内部超用 + 废卡 + 接口失败」——避免任务端多报次数后仍留下残额被继续使用；接入方应先查再扣，且仅在核销成功后执行任务。
- 取舍：超用与用完对外同一类失败（复用 `CODE_USED`），不新增错误码；清零与负剩余对接入方都只表示废卡。
- 取舍：不做预扣与退回；查询只作预检，以核销当场结果为准。
- 取舍：`count` 上限 1000，防止恶意大次数；核销 IP 规则不变。

## 不做

- 按时长计费、不绑定设备、不限次数的卡密。
- 签发后增减卡密次数（含管理员把超用改回）。
- 任务失败自动退回。
- 核销时附带备注（如分享链接）。
- 超额时仍返回成功并让接入方按请求次数执行任务。

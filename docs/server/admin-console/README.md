# 管理后台

## 目标

个人使用的极简网页后台：创建软件，点进软件就能管理它的卡密、卡密批次与已激活设备。

## 需求

首次使用先进入初始化引导页；日常使用的页面只有六个：

```text
首次初始化（创建管理员）→ 登录 → 软件列表 → 软件的卡密页 → 激活详情
                                          ↘ 卡密批次列表
                               ↘ MCP 接入
```

- 首次初始化：系统中还没有任何管理员时，访问任意页面都跳到初始化页；填写用户名和密码（需确认密码）后创建唯一的超级管理员，自动登录进入软件列表。管理员创建后初始化页永久失效，再访问跳到登录页。
- 软件列表（登录后首页）：查看全部软件；新建软件；编辑名称、换设备策略、禁用状态；点击软件进入它的卡密页。
- 软件的卡密页：批量签发卡密（单个填 1）并列出本批卡密便于复制；按批次或全部导出 CSV；按卡密或设备搜索已激活记录；禁用或取消禁用某条激活。
- 卡密批次列表：查看该软件的全部卡密批次，可禁用某一批次。
- 激活详情：只读查看当前绑定设备与全部换设备记录。
- MCP 接入：展示可直接复制的 MCP 配置，地址随当前访问后台所用的域名或 IP 变化。
- 顶栏只有：MCP 接入、修改密码、退出。
- 只有一个管理员账号，在首次初始化页创建；登录 12 小时有效；连续 5 次登录失败暂停登录 15 分钟。
- 服务部署在反向代理（nginx / caddy）后时，页面展示的地址使用代理转发的域名与协议。
- 签发、导出、禁用等业务规则见[卡密管理](../key-management/README.md)与[设备绑定](../device-binding/README.md)。

## 方案

- 新增：Module `server/console`；接口见 [server/console/interface.yaml](../../../server/console/interface.yaml)。
- 复用：`server/keys` 的 product 与卡密批次管理、签发、导出函数；接口见 [server/keys/interface.yaml](../../../server/keys/interface.yaml)。
- 复用：`server/activation` 的激活记录查询、详情与禁用函数；接口见 [server/activation/interface.yaml](../../../server/activation/interface.yaml)。
- 取舍：后台不直接读写任何数据表，全部通过上述函数操作。
- 取舍：不使用 Django 自带后台，只做六个页面，保持极简。
- 取舍：不再校验访问地址（原实现只校验可伪造的 Host 头，并非真实防护），部署时无需先登录后台添加地址。
- 取舍：管理员在首次初始化网页中创建，不提供命令行或环境变量建号；未初始化期间由初始化页拦截全站，建号后该页永久关闭。

## 不做

- 用户、组等账号管理页面。
- 删除软件或卡密批次；软件标识创建后修改。
- 修改或删除激活记录与换设备记录。

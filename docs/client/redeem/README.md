# 核销接入规范

## 目标

规定接入方如何调用服务端查询与核销按次数卡密。按次数卡密按次数扣减、不绑定设备，网页服务、桌面软件等任何接入方都可按业务选用。本仓库不提供接入方实现，由接入方按本规范自行接入。

## 要实现的

- 用户在接入方填写任务参数（如分享链接）与卡密。
- 执行任务的一方可先调用状态查询接口（只读），查看卡密是否可核销及剩余次数；也可直接核销。
- 执行任务的一方调用核销接口，上传用户输入的卡密与可选扣减次数 `count`（省略或为 1 时每次扣 1 次）；卡密可带或不带连字符、空格，大小写均可，原样上传即可。
- 核销成功后再执行任务，并可向用户展示返回的剩余次数；核销失败则不执行，并按错误码提示用户。
- 若请求扣减超过剩余次数，服务端会将该卡密作废（内部记超用），并返回失败；此后该卡密不可再核销。接入方应先查剩余再按不超过剩余的 `count` 核销，避免误作废。
- 接口请求、响应与错误码以服务端 [server/redeem/interface.yaml](../../../server/redeem/interface.yaml) 为准。
- 本规范与核销相关接口同样可从服务端只读 MCP 获取，见[激活接入规范](../activation/README.md)中的 MCP 说明。

## 关键约束

- 核销结果须由执行任务的一方直接从服务端取得：任务由后端执行时由后端调用核销接口，不能让浏览器或其它客户端调用后再转告后端结果。
- 状态查询不扣次数，但不能当作扣减锁：查与核销之间次数可能被其它请求改掉，以核销返回为准。
- 核销成功即视为已按 `count` 使用，任务失败不会退回；接入方须先完成任务参数的校验（如分享链接格式）再核销。
- 接入方须按错误码给出明确提示，至少区分：卡密无效、次数已用完或不足（卡已废）、卡密不是按次数卡密、卡密批次或 product 已禁用、请求参数非法。

## 失败场景

- 网络无法连接服务端。
- 卡密签名无效或所属批次已禁用。
- 卡密次数已用完，或本次扣减超过剩余（卡被作废）。
- 卡密属于设备激活 product。
- 卡密所属 product 已禁用。
- `count` 非法（非正整数或超过上限）。

## 解决步骤

1. 校验用户提交的任务参数。
2. （建议）调用状态查询，确认剩余次数足够。
3. 调用核销接口（code，及需要的 count），成功后执行任务，可展示剩余次数。
4. 核销失败时按错误码提示用户，不执行任务。

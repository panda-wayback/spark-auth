# 核销接入规范

## 目标

规定接入方如何调用服务端核销按次数卡密。按次数卡密每次核销扣 1 次、不绑定设备，网页服务、桌面软件等任何接入方都可按业务选用。本仓库不提供接入方实现，由接入方按本规范自行接入。

## 要实现的

- 用户在接入方填写任务参数（如分享链接）与卡密。
- 执行任务的一方调用核销接口，上传用户输入的卡密；卡密可带或不带连字符、空格，大小写均可，原样上传即可。
- 每次核销扣 1 次；核销成功后再执行任务，并可向用户展示返回的剩余次数；核销失败则不执行，并按错误码提示用户。
- 接口请求、响应与错误码以服务端 [server/redeem/interface.yaml](../../../server/redeem/interface.yaml) 为准。
- 本规范与核销接口同样可从服务端只读 MCP 获取，见[激活接入规范](../activation/README.md)中的 MCP 说明。

## 关键约束

- 核销结果须由执行任务的一方直接从服务端取得：任务由后端执行时由后端调用核销接口，不能让浏览器或其它客户端调用后再转告后端结果。
- 核销成功即视为已使用 1 次，任务失败不会退回；接入方须先完成任务参数的校验（如分享链接格式）再核销。
- 接入方须按错误码给出明确提示，至少区分：卡密无效、次数已用完、卡密不是按次数卡密、卡密批次或 product 已禁用。

## 失败场景

- 网络无法连接服务端。
- 卡密签名无效或所属批次已禁用。
- 卡密次数已用完。
- 卡密属于设备激活 product。
- 卡密所属 product 已禁用。

## 解决步骤

1. 校验用户提交的任务参数。
2. 调用核销接口（code），成功后执行任务，可展示剩余次数。
3. 核销失败时按错误码提示用户，不执行任务。

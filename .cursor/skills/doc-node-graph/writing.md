# Doc Node Graph — Writing

写/改 `docs/**` 前须服从 `workflow.mdc` 门禁。

## 建节点

- 已裁定要建，且需独立理解/调用 → 一目录一 README。
- 同一能力只建一处。
- 禁止提前建未轮到的目录。
- 否则留在父解决步骤，不建目录。

## 写节点算法

```text
写目标 + 要实现的
写解决步骤
  ├─ 未裁定 → 不改解决步骤；给判断；禁止建子目录
  ├─ 已裁定且本页可写完 → 写入本页
  ├─ 已裁定需子页且不存在 → 只建空架子并链接；停止
  └─ 本页写完 → 停止
更新 docs 索引（若有变更）
```

空架子：`目标` + `要实现的`（已知部分）+ `解决步骤：待拆`。禁止同轮再拆其内部。

解决步骤需多模块实现 → 按 `pseudo-software.md` 展开，裁定后生成各模块 `spec.yaml` + `AI.md`。

## 选下一步算法

```text
1. 根 docs 解决步骤顺序
2. 根 docs 索引「推进」类语句若与现状冲突 → 先改索引再往下
3. 第一个未完成节点/步骤
4. 待拆/未裁定 → Agent 给最佳草案；用户裁定前不写 docs
5. 仍有未完成子链接 → 进入子节点
6. 裁定后写当前项；本轮停止
```

一轮一步。禁止同轮递归铺开。

## 链接

- 可见文字 = 仓库根路径。
- 对能力节点只用其 `目标` / `要实现的`，禁止抄解决步骤。
- 点名依赖时覆盖需求涉及的参与方；禁止只写一层。

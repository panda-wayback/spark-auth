# Doc Node Graph

服从 `.cursor/rules/workflow.mdc`「方案先行」。本文件只规定 **docs 节点形态** 与 **下层 Skill 调度**。

## 触发

- 探讨方案
- 写/改 `docs/**`
- 选下一步
- 进入实现前自检

## 节点形态

能力节点标题顺序：`目标` → `要实现的` → `解决步骤`（`状态` 可选）。

| 标题 | 写什么 |
|---|---|
| 目标 | 是什么、做成什么样 |
| 要实现的 | 谁/场景/能做什么；关键约束与失败 |
| 解决步骤 | 已裁定大步骤；须能看出做得到；候选须标未选定；子链接与顺序 |

- 需求优先；短句/列表。
- 未裁定的解决步骤保持「待拆」。

## 调度

| 场景 | 读 |
|---|---|
| 建节点 / 推进解决步骤 | `writing.md` |
| 判断 docs 是否够进入实现 | `ready-check.md` |
| 已裁定且需多模块详细设计 | `pseudo-software.md` |

## 模板

```markdown
# <能力名>

## 目标

## 要实现的

- …

## 解决步骤

1. …
```

`docs/README.md` 可为根能力页。索引表/A→B 可选；禁止为凑索引造空表。
